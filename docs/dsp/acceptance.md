## What MM3 actually uses (runtime + recomp evidence, 2026-10-08)

Method: temporary instrumentation (reverted) in the live recompiled build through boot, menus and gameplay; replay probes of the v3 captures; and a guard-page read trap on host memory.
- DMA descriptors: exactly eight distinct control words across GP/EP: 0x0059E0/0x0059E2/0x005BE0 (format 6, scratch F), 0x0059D2 (format 6, scratch-circular E), 0x004BD0/0x004BD2 (format 2, E), 0x0049E2 (format 2, F), 0x400603 (format 1, interleaved, output FIFO 0). Formats 0 and 3, input routes 2..D and output routes 4..D are never issued.
- Format-6 GP mixbin writes (GP scratch 0x8000-0xAFFF) and EP format-6 reads (EP scratch 0x10000-0x12400) hit the same physical pages (0x478000-0x47AFFF). The packing is self-consistent and is what produces the verified PCM.
- The only format-2 buffer that leaves the DSPs is GP scratch 0xB000 (0xA00 bytes, physical 0x454000). A PAGE_NOACCESS trap on that page recorded zero CPU/VP reads through boot and gameplay, so format 2's MSB-vs-LSB packing is not observable by MM3. All other format-2 traffic is GP scratch-circular round trips, where the packing cancels.
- Executed instruction coverage: no DEBUG/DEBUGcc (OnCE), no cache control, no SA mode, no MAX/MAXM, no Y-space accesses outside YRAM, no out-of-bounds X reads.

Conclusion: every DSP feature MM3 exercises is implemented and verified. The remaining rows (formats 0/3, extra routes, OnCE, Y peripherals, cycle timing) are unreachable from MM3's microcode and have no defining reference (pinned xemu asserts on them). They stay as explicit error stops rather than invented behavior. A title that issues them will log the descriptor, which gives the data needed to implement them then.
